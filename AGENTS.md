# AGENTS.md — AI Coding Assistant Reference Guide

This document provides architectural context, implementation patterns, and engineering guidelines for AI coding assistants and developers working on the **Fresh Fridge** codebase.

---

## 🏗️ System Architecture Overview

Fresh Fridge is a multi-user, internationalized web application that leverages artificial intelligence to manage fridge inventory and suggest recipes.

* **Frontend**: Single Page Application built with **React**, **Vite**, **Tailwind CSS**, and **Framer Motion** (`motion/react`).
* **Backend**: **Express** web server (configured with Vite middleware in development mode and static file serving in production mode).
* **Database**: **PostgreSQL 18** (persisting user details, inventories, and saved recipes).
* **AI Integration**: **Gemini 3.5 Flash** (powering receipt/photo scanning and personalized recipe generation).

## 🌎 Internationalization (i18n)

We implement lightweight, high-performance localization for **English (`en`)** and **French (`fr`)** without external dictionary dependencies.

* **Context Module**: [`src/LanguageContext.tsx`](file:///Users/hibonfrancoisxavier/antigravity/Fresh-Fridge/src/LanguageContext.tsx)
* **Default Logic**: Detects `navigator.language` on first mount, falling back to English. Persists user choices to `localStorage` under `fresh-fridge-lang`.
* **State Hook**: Use the custom `useLanguage()` hook in any React component to access:
  - `language`: `'en' | 'fr'`
  - `setLanguage(lang: Language)`: Changes active dictionary and saves to local storage.
  - `t(key, replacements?)`: Dynamic translation lookup supporting replacement keys (e.g. `t('expiryDays', { days })`).
  - `dateLocale`: The `date-fns` locale configuration (`fr` or `enUS`) for localized date strings.

> [!CAUTION]
> When adding new user-facing labels, buttons, or error messages, **always** extend both the `en` and `fr` dictionaries in `LanguageContext.tsx` and access them via `t()`. Do not use hardcoded text nodes in UI components.

## 🔑 Authentication & Security Model

The system uses stateless JSON Web Token (JWT) sessions.

* **User Data Hash**: Hashed on signup/signin via `bcryptjs` with salt factor 10.
* **Token Issuance**: JWT signed using `jsonwebtoken` with a 7-day expiration (`expiresIn: '7d'`).
* **Secure Middleware**: [`server.ts`](file:///Users/hibonfrancoisxavier/antigravity/Fresh-Fridge/server.ts) contains `authMiddleware`, which:
  - Checks the `Authorization: Bearer <token>` header.
  - Decodes the secure `userId` and attaches it as `req.userId`.
  - Rejects unauthorized traffic with a `401 Unauthorized` JSON error.
* **Client Synchronization**: [`src/App.tsx`](file:///Users/hibonfrancoisxavier/antigravity/Fresh-Fridge/src/App.tsx) uses a wrapper `fetchWithAuth(url, options)` that injects the active token and automatically signs out the user if a `401` response occurs.

## 🗄️ Database & Migrations Pipeline

We use a version-controlled, programmatic migration system to manage our PostgreSQL database schema.

### 1. Migrations Directory
* **Location**: [`migrations/`](file:///Users/hibonfrancoisxavier/antigravity/Fresh-Fridge/migrations/)
* **Format**: TypeScript files using `node-pg-migrate` builders (e.g., `[timestamp]_initial_schema.ts`).
* **Rules**: Always define both the `up` function (schema changes) and the `down` function (reversing schema changes). Use uppercase for actions (e.g., `onDelete: 'CASCADE'`).

### 2. Runtime Execution ([`db.ts`](file:///Users/hibonfrancoisxavier/antigravity/Fresh-Fridge/db.ts))
On server startup, `initDb()` is executed programmatically. It dynamically resolves the target directory based on the active environment:
* **Development**: Loads TypeScript files directly from `migrations/`.
* **Production**: Loads transpiled JavaScript files from `dist/migrations/`.

### 3. Build & Transpilation ([`package.json`](file:///Users/hibonfrancoisxavier/antigravity/Fresh-Fridge/package.json))
The migrations are compiled into production-safe JavaScript using `esbuild` during the build step:
```bash
esbuild migrations/*.ts --outdir=dist/migrations --platform=node --format=cjs
```

## 🚨 Guidelines for Future Agents

1. **Database Schema Modifications**:
   - Never write raw DDL queries (e.g., `CREATE TABLE`, `ALTER TABLE`) inside application files or running server scripts.
   - Always generate a new migration file inside `migrations/` named `[timestamp]_action_description.ts` and write migrations using the `MigrationBuilder` API.
2. **Prevent SQL Injection**:
   - **Never** construct SQL queries using string concatenation (e.g., `'SELECT * FROM users WHERE email = ' + email`).
   - **Always** use parameterized queries (e.g., `pool.query('SELECT * FROM users WHERE email = $1', [email])`).
3. **i18n Conformity**:
   - Ensure any modified API prompts (such as recipes generated by Gemini AI) inspect the active language parameters and generate AI content in the user's selected language.
4. **Container Compatibility**:
   - Verify that any new environment variables are documented in the `README.md` and added to `docker-compose.yml` to maintain sane containerization behavior.
